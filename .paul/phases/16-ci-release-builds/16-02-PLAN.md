<objective>
## Goal
`.github/workflows/ci.yml`. It runs `on: push: branches [main]` and `pull_request`, with a
concurrency group that cancels superseded runs. Actions are pinned by commit SHA. It has three jobs.

**`linux-gate` (ubuntu-24.04)** is the local gate, verbatim:
- apt: JUCE's dev packages, `ninja-build`, `xvfb` and `x11-utils`. GCC 13, Python 3 and Node 20
  are already on the image.
- JUCE 8.0.12, shallow-cloned to `$RUNNER_TEMP/JUCE`.
- Configure `build-linux` (Release).
- Run `scripts/headless-x.sh $JUCE scripts/validate-plugin.sh`. That gives three verdicts:
  pluginval Debug, pluginval Release, and the Debug suite with assertions as failures. The design
  gates run as part of each build.

**`linux-portable` (ubuntu-24.04, Docker)** runs `JUCE_PATH=$RUNNER_TEMP/JUCE
scripts/build-linux-portable.sh`, which covers the floor check and the clean-22.04 suite.

**`windows` (windows-2022), in Git Bash:**
- clone JUCE;
- `cmake -G "Visual Studio 17 2022" -A x64 -DFORROBOX_TESTS=ON -DJUCE_PATH=…`, then build Release;
- run `ForroBoxTests.exe` and judge its result line;
- `OBJDUMP=llvm-objdump scripts/check-pe-runtime.sh` on the VST3 binary, the standalone and the
  test exe;
- `scripts/validate-plugin.sh --windows <bundle>`, which runs pluginval natively.

**Script changes it needs:**
- **`validate-plugin.sh --windows`:** under Git Bash (`MSYSTEM` set, no `wslpath`), skip the
  WSL/UNC copy, run `pluginval.exe` directly, and pass the bundle with `cygpath -w`. The WSL path
  is unchanged.
- **`check-pe-runtime.sh`:** `${OBJDUMP:-objdump}`. Confirm that `llvm-objdump -p` prints
  `DLL Name:` lines for COFF imports, or adapt the match.
