<decisions>
## `MIX` keeps its meaning; the convolution gets `conv_mix`

`PLANNING.md:841` says "`MIX` becomes the convolution wet amount". Taken literally that makes
`char_mix` — a live, automatable parameter since 03-03 — mean two different things depending on
whether an IR happens to be loaded, so one automation lane would change what it does the moment a
project loads a file. **The user chose the other reading at 09-07 planning.**

This is the resolution PROJECT.md already names for prototype/plugin conflicts, and the precedent is
exact: 07-03 added `midi_gate` as the 46th parameter **with no UI**, because "PLANNING.md specifies
no such control and the design mandate forbids inventing one, so hosts expose it generically". Same
shape, same answer. `conv_mix` is the **47th**, and the count is asserted in four places in
`tests/StateRoundTripTest.cpp` as a deliberate tripwire — moving it is a conscious act.

The on-chassis `MIX` knob is untouched and keeps blending the character bus.

## The convolution runs BEFORE the mix bus, and the ordering is a decision

`MixBus::process` is a **per-sample loop** — character bus, limiter and master interleaved with
per-sample smoothing. `juce::dsp::Convolution` is block-based and cannot go inside it, and splitting
that loop would restructure the one audio path this project has kept proven since 03-03.

So the stage runs on the summed voices, before `MixBus`: **voices → convolution → character →
limiter → master.** Two consequences worth stating rather than discovering:

- The character bus colours the convolved signal, not the reverse. Musically that is a tape machine
  after a room mic, which is ordinary — but it is not the literal reading of the side panel's
  `TIMBRE / CONVOLUTION` ordering, and this line is where that is recorded.
- **The limiter still protects the output.** An IR with gain cannot push past the limiter, which is
  the safety property that decides the placement.

## Latency is zero or it is REPORTED

`juce::dsp::Convolution`'s default (uniform) mode adds latency equal to its block size. A plugin
that adds unreported latency plays late against every other track in the host.

Use the zero-latency head so nothing needs reporting, OR call `setLatencySamples` with what
`getLatency()` returns. Either is acceptable; silence is not. A test asserts the reported latency
matches the stage's actual latency.

## A missing IR is dry, not broken

The path persists; the audio does not. A project saved on another machine, or whose IR was moved,
must load, play dry, and keep the stored path — the same rule `State::readFrom` applies to an
unrecognised profile (07-02) and an unrecognised groove (09-06).
</decisions>
