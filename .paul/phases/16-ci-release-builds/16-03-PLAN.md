<objective>
## Goal
`ci.yml` gains `push: tags: ['v*']`.

**On a tag:**
- **`linux-portable`** adds a step after the portable build: `scripts/package-release.py
  --platform linux --artefacts build-portable/ForroBox_artefacts/Release --out dist/`, then uploads
  `dist/` as the artifact `package-linux`.
- **`windows`** does the same with `--platform windows` from `build/ForroBox_artefacts/Release`,
  uploading `package-windows`.
- **New job `release`:** `needs: [linux-gate, linux-portable, windows]` and
  `if: startsWith(github.ref, 'refs/tags/v')`, with `permissions: contents: write`. Only this job
  gets write access.
  1. **Version check.** The tag `vX.Y`, with an optional `-suffix`, must match `CMakeLists.txt`'s
     `X.Y.*`. Otherwise it FAILS before anything is created, so a tag on the wrong commit cannot
     produce a mislabelled release.
  2. Download both package artifacts.
  3. `scripts/package-release.py --checksums dist/`, then `sha256sum -c`.
  4. `gh release create "$TAG" --draft --verify-tag --title "Forró Box <version>" --generate-notes`
     with the two archives and `SHA256SUMS.txt`.
     - A pre-release suffix (`-rc…`, `-test…`) adds `--prerelease`.
     - The notes are GitHub's generated ones; the user edits them before publishing, as v0.2's were
       written by hand.

**Publishing stays the user's act (Phase 16 planning).**

## Purpose
- **ROADMAP Phase 16:** "the release packages for Linux and Windows on a tag".
- It replaces the hand assembly of v0.1 and v0.2 with the same gates plus 16-01's reproducible
  packaging. The release job runs only after all three gate jobs pass.
</objective>

## AC-1: A tag makes a draft release
```gherkin
Given a throwaway tag matching the CMake version (e.g. v0.2-ci-proof on main)
When CI runs
Then the three gate jobs pass, both packages are built, and a DRAFT pre-release exists carrying ForroBox-<v>-linux-x64.tar.gz, ForroBox-<v>-windows-x64.zip and SHA256SUMS.txt
  And downloading them, sha256sum -c passes and both archives list the v0.2 layout
  And afterwards the draft and the tag are deleted
```

## AC-2: A mismatched tag makes nothing
```gherkin
Given a throwaway tag whose X.Y differs from CMakeLists (e.g. v9.9-ci-proof)
When CI runs
Then the release job FAILS at the version check and no release (draft or otherwise) exists; the tag is then deleted
```

  <name>Task 1: The tag path in the workflow</name>
  <files>.github/workflows/ci.yml, README.md</files>
  <action>
    - **Triggers:** add `tags: ['v*']` under `push`.
    - **Packaging steps** with `if: startsWith(github.ref, 'refs/tags/v')`: `package-release.py`
      into `dist/`, then `actions/upload-artifact` (pinned) as `package-linux` / `package-windows`.
      - On Windows, Python is `python` and runs under the Git Bash defaults.
      - `SOURCE_DATE_EPOCH` comes from the tagged commit (`git log -1 --format=%ct`), so both
        runners stamp the same time. Checkout depth 1 has that commit.
    - **The `release` job:**
      - checkout, then the version check: parse the tag with a regex
        `^v([0-9]+)\.([0-9]+)(-[A-Za-z0-9.]+)?$` and compare it with the CMake major.minor;
      - `actions/download-artifact` (pinned) for both packages into `dist/`;
      - `--checksums dist/` and `sha256sum -c`;
      - `gh release create … --draft`, plus `--prerelease` when the suffix is present;
      - `GH_TOKEN: ${{ github.token }}`.
    - **README:** "Releasing: bump `project(… VERSION)`, commit, push a `vX.Y` tag; CI attaches
      the packages to a draft release — review and publish it."
  </action>
  <verify>YAML parses; a push to main still runs exactly the three jobs (AC-3)</verify>
