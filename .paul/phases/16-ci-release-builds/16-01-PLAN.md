<objective>
## Goal
**`scripts/package-release.py`**, in Python because it runs on the Linux and Windows CI runners
alike and this repo's gates are already Python. Two modes:

- **`--platform linux|windows --artefacts <dir> --out <dir>`** writes
  `ForroBox-<version>-<platform>-x64.{tar.gz|zip}`, where `<version>` comes from
  `CMakeLists.txt`'s `project(… VERSION …)` (one source of truth). Inside:
  - one top folder holding the VST3 bundle (copied whole), the standalone (`ForroBox` or
    `ForroBox.exe`), `LICENSE`, `ABOUT.md`, `NOTICE.md`, `INSTALL.txt` and `licenses/*-OFL.txt`
    from `assets/fonts`;
  - that is exactly the v0.1/v0.2 layout.
- **`--checksums <dir>`** writes `SHA256SUMS.txt` over the archives in `<dir>`, in the format the
  v0.2 release used.

**Reproducible.** Entries are sorted, mtimes fixed (`SOURCE_DATE_EPOCH`, else the commit time),
uid/gid 0, and file modes normalised (0755 for executables, 0644 otherwise). The same artefacts give
byte-identical archives, so a checksum means something.

**Templates.** `packaging/INSTALL-{linux,windows}.txt.in` are the v0.2 INSTALL.txt files with
`@VERSION@` and `@TAG@`, and with the 0.3 requirements:
- Linux: glibc 2.35 (Ubuntu 22.04, Debian 12, Fedora 36), the C++ runtime built in;
- Windows: no redistributable.

**It refuses a wrong package.** Each listed input must exist. The VST3 must contain its platform's
binary (`x86_64-linux/ForroBox.so` or `x86_64-win/ForroBox.vst3`) and the moduleinfo, whose
`"Version"` must equal `<version>`, so a stale build cannot be packaged under a new number.

## Purpose
- **ROADMAP Phase 16:** "the release packages … the v0.1/v0.2 package layout and `SHA256SUMS.txt`".
- **Measured:** v0.1 and v0.2 were assembled by hand, and v0.2 needed a re-zip for a missing
  directory entry. CI (16-02, 16-03) calls this script on each runner.
</objective>

<task type="auto">
  <name>Task 1: The script and the templates</name>
  <files>scripts/package-release.py, packaging/INSTALL-linux.txt.in, packaging/INSTALL-windows.txt.in, README.md</files>
  <action>
    - Use the standard library only (`tarfile`, `zipfile`, `hashlib`, `argparse`, `json`), so no
      dependency.
    - Read the version from `CMakeLists.txt` with a regex anchored on `project(ForroBox VERSION`.
      The tag is `v<major>.<minor>`, following `v0.1` and `v0.2`.
    - Stage into a temp dir, then archive with sorted entries, a fixed mtime, uid/gid 0 and
      normalised modes.
      - Zip: explicit directory entries, the top folder included. That was v0.2's re-zip lesson.
      - Tar: gzip with `mtime=0` in the gzip header.
    - Validate before writing:
      - inputs exist;
      - the platform binary is inside the bundle;
      - moduleinfo `Version` equals the CMake version;
      - no `@…@` placeholder survives in INSTALL.txt.
    - Templates: copy the v0.2 INSTALL.txt text (saved in the scratchpad from the release), then
      update the requirements as above.
    - README: one paragraph, "Releases are packaged by `scripts/package-release.py` (CI runs it on
      a tag)".
  </action>
  <verify>Runs on build-portable/ and on the Windows Release artefacts; archives written</verify>
  <done>AC-1 (production)</done>
</task>

<task type="auto">
  <name>Task 2: Prove layout, reproducibility, refusals, checksums</name>
  <files>scripts/package-release.py (a --self-test is optional; the proofs can be shell runs recorded in the SUMMARY)</files>
  <action>
    - **Layout:** compare each archive's entry list, with directory slashes stripped, against the
      v0.2 archive's (already in the scratchpad), with the version substituted. They must be equal.
    - **Reproducible:** package twice, then compare the SHA256s.
    - **Refusals, each must fail with nothing written:**
      - a copy of the artefacts without a licence;
      - without the platform binary;
      - with moduleinfo `Version` edited.
    - **Checksums:** `--checksums`, then `sha256sum -c SHA256SUMS.txt`.
    - Open the Linux tarball in a clean `ubuntu:22.04` (the 15-02 runtime image) and run the
      standalone's `ldd`, so packaging did not break the bundle.
  </action>
  <verify>Layout equal to v0.2's; two runs byte-identical; three refusals; sha256sum -c OK; ldd clean from the unpacked tarball</verify>
  <done>AC-1, AC-2, AC-3, AC-4</done>
</task>
