<objective>
## Goal

Selecting `CICLOTRON™` degrades the whole chassis: a saturate/contrast filter, a scanline overlay
flickering on a 4 s step loop, chromatic aberration on the character's own name, and its sub-label
`TOTAL DISTORTION™` blinking in `--danger`. Deselecting it restores the chassis exactly.

## Purpose

It is the LAST item in Phase 8's scope, and the phase completes with it. `PLANNING.md:629-635`
specifies it; `PLANNING.md:628` states the reason it is worth building at all — *"Ciclotron™ is an
in-joke and is treated as one visually."*

Three earlier plans deferred work to this one BY NAME, and this plan is where those debts come due:

- `PluginProcessor.cpp:188` scheduled the `™` on the character's name for Phase 8, *"alongside the
  scanline overlay and the chromatic aberration that go with it"*. `verify-profiles.py:252-258`
  compares the name with that one character stripped, and says so.
- 06-05 confirmed with the user that the visual treatment stays in Phase 8 — Phase 6 shipped the
  selection and the audio.
- `STATE.md` carries an 08-04 deferral: the easter egg's design constants live in two headers chosen
  by which gate reads them. This plan adds a third group of exactly that kind, so it either fixes
  the split or repeats it.

## Output

- `steps()` semantics on the shared keyframe track — CSS `steps(1)` HOLDS a value; it does not ease
- One effect layer, re-rendering the chassis ONCE for however many treatments are active
- The character's name carrying its own trademark at last, and the cross-check comparing it verbatim
</objective>

  <name>Task 1: `steps()`, and the easter egg's constants given one home</name>
  <files>src/Surface.h, src/Surface.cpp, src/Effects.h, src/DrunkOverlay.h, src/Chassis.h, src/TimbreRow.h, scripts/verify-geometry.py, tests/UiTest.cpp</files>
  <action>
    TWO THINGS, and they are one task because the second is what stops the first from being
    written into a third scattered home.

    **`steps()` on the keyframe track.** `KeyframeLoop` and `keyframeValueAt` ease between every
    adjacent pair — correct for 08-04's two tracks, which are `ease-in-out`, and WRONG for both of
    this plan's, which are `steps(1)`. CSS `steps(1)` is `steps(1, end)`: the value HOLDS at each
    stop until the next one is reached. An eased flicker is a smooth fade where the design asks for
    a hard cut, and it is the plausible substitute this project's checks exist to refuse — the same
    class as the sine that 08-04's sway rejected.

    The timing belongs to the TRACK, not to the caller: `forrobox.css` declares it per animation
    (`4s steps(1)`, `1.4s steps(1)`, against `6s ease-in-out`), so it is a property of the stop
    list. Add it as such, so a caller cannot pair the wrong one with a track.

    **One home for the design constants.** 08-04 left the easter egg's eight constants split across
    `DrunkOverlay.h` and `Chassis.h` — and `Chassis.h`'s own comment concedes the reason was *"this
    header is the one enrolled in `verify-geometry`"*, which is enrolment deciding where a number
    lives. STATE.md carries it as a deferred item with this named fix, and this plan adds a THIRD
    group of the same kind, so the choice is to fix the split or to repeat it.

    `src/Effects.h` holds `namespace drunk` and `namespace ciclo`, is enrolled in
    `GEOMETRY_HEADERS`, and every constant in it is compared or excused BY NAME — which is what
    `kOnsetPercent` and `kSpanPercent` escape today.

    MOVE, do not copy. A constant that exists in two places is the divergence this project has
    fixed four times.

    `ciclo` carries: the scanline's period and its two bands, the overlay's base opacity, the
    flicker's four dip stops and its 4 s period, the filter's saturate and contrast factors, the
    aberration's 1.2 px offset and its two 70% weights, and the blink's 1.4 s period and its stops.
    Every one has a design source — css:102-116 and css:425-427 — so every one gets an expectation,
    not an excuse.
  </action>

<task type="auto">
  <name>Task 2: the chassis degrades, on one re-render</name>
  <files>src/DrunkOverlay.h, src/DrunkOverlay.cpp, src/Chassis.h, src/Chassis.cpp, tests/UiTest.cpp</files>
  <action>
    css:109's `filter: saturate(0.9) contrast(1.06)` on the whole chassis, and css:102-108's
    scanline overlay at 50% opacity, flickering.

    ONE RE-RENDER FOR ALL OF IT, and this is the task's architectural decision rather than a
    detail. A second overlay beside `DrunkOverlay` would be the obvious shape and it costs a THIRD
    chassis paint whenever both are active — 08-04 measured one at 4.5 ms and the doubled frame at
    12.0 ms, so a third would put a plugin at CACHAÇA 100 with CICLOTRON selected near 20 ms of a
    33 ms budget, for a treatment that is a joke. The layer re-renders the chassis once and applies
    whatever passes are active to those pixels. `DrunkOverlay` is no longer the right name for it.

    THE ORDER IS THE STYLESHEET'S, and it is observable. `filter` applies to the element itself;
    `::before` (the scanlines) is z-index 58 and `::after` (08-04's wash) is 60. So: filter the
    chassis's own pixels, composite the scanlines over that, then screen the wash over both. Getting
    it backwards is invisible in a still and wrong in principle — assert the composition rather than
    eyeballing it.

    THE SCANLINES ARE NOT SCREEN. `rgba(0,0,0,0.14)` is a DARKENING composite, source-over, which
    is the exact operation 08-04's header argues the wash must not use. Two passes, two blend modes,
    and the reason each has the one it has stated where it is written. `screenOnto`'s "no pixel
    darkens" check does not generalise to this pass and must not be copied onto it.

    `repeating-linear-gradient(0deg, rgba(0,0,0,0.14) 0 1px, transparent 1px 3px)` is a function of
    DEVICE Y ALONE, so a partial repaint needs the same treatment `originInWash` gives the gradient
    — 08-04's header names this as the thing 08-05 must not inherit blindly. The
    partial-repaint-matches-a-full-one check applies to it unchanged, at scale 1 AND at a fractional
    one.

    THE TRIGGER IS THE PARAMETER, read where CACHAÇA is read. `Chassis::pollVisualisers` already
    reads one raw parameter for the easter egg; the character is the second. NOT the side panel's
    selection — a host automating `ids::timbre` with no editor open must leave an editor that opens
    later in the right state, which is 05-03's ruling about tiling one subsystem over.

    MEASURE IT, as 08-04's Task 1 did, and report the frame cost with neither treatment, with one,
    and with both. The stop condition is the same 16 ms.

  here is switchable, because the design source specifies no switch.
