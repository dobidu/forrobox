<objective>
## Goal
JUCE assertions in the test suite become **failures**.
- The Debug tree is built with `JUCE_LOG_ASSERTIONS=1`, so every `jassert` goes through
  `Logger::writeToLog`.
- The harness installs a Logger that counts them. Any assertion outside an
  `fbtest::ExpectAssertions` scope fails the run, naming its `file:line`.
- `scripts/validate-plugin.sh` builds and runs that suite as part of the gate.
- Then the six sites measured at planning are each fixed, or declared expected where a test
  deliberately exercises a guarded path.

## Purpose
- The suite has only ever run in Release, where `jassert` compiles out. Measured at planning: the
  Debug suite passes 4999/4999 while logging **3489 assertion failures at 6 sites**.
- Two of those are production defects that no check could see: `MixBus`'s inverted `jlimit` at
  extreme sample rates, and three components grabbing focus while not showing.
- 11-06 (`loadProfile` on a loader thread) can only be observed this way. The instrument comes
  first, by the order the user chose.

## Output
- An assertion-aware harness and a gate that runs the Debug suite
- Six sites closed. Debug suite: 0 unexpected assertions
</objective>
