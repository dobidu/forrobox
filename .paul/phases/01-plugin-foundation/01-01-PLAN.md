<objective>
## Goal

Stand up the CMake project and JUCE plugin skeleton: a VST3 + Standalone **instrument** target
named Forró Box that configures, builds and loads on Linux, presenting a silent processor and an
empty editor fixed to the 1200×780 / 20:13 design geometry.

## Purpose

Every later phase attaches to this scaffold — parameters (01-02), the Windows build (01-03), the
clock (Phase 2), voices (Phase 3) and the chassis (Phase 4). Getting the target flags right now
(`producesMidi`, `wantsMidiInput`, synth flag, aspect-constrained editor) avoids re-plumbing the
plugin type later, which is the one change that ripples through everything.

## Output

- `CMakeLists.txt` — JUCE 8.0.12 via FetchContent with a `JUCE_PATH` local override
- `src/PluginProcessor.{h,cpp}` — `juce::AudioProcessor` subclass, silent, no parameters yet
- `src/PluginEditor.{h,cpp}` — `juce::AudioProcessorEditor`, 1200×780, aspect-constrained, resizable
- `.gitignore` — build directories and JUCE fetch cache
- Build artifacts: `build-linux/ForroBox_artefacts/**/VST3/Forró Box.vst3` and the Standalone binary
</objective>

## AC-1: Project configures with JUCE resolved locally

```gherkin
Given a clean checkout with no build directory and JUCE 8.0.12 present at ~/JUCE
When `cmake -B build-linux -G Ninja -DJUCE_PATH=$HOME/JUCE -DCMAKE_BUILD_TYPE=Release` runs
Then configuration succeeds with no error
And the configure log states that the local JUCE at ~/JUCE was used rather than a download
And no network fetch of JUCE is attempted
```

## AC-2: Plugin declares the correct format and capabilities

```gherkin
Given the configured project
When the CMake plugin target is inspected
Then FORMATS is VST3 and Standalone
And IS_SYNTH, NEEDS_MIDI_INPUT and NEEDS_MIDI_OUTPUT are all TRUE
And PLUGIN_NAME is "Forró Box" with PRODUCT_NAME "ForroBox"
And the processor reports acceptsMidi() == true, producesMidi() == true, isMidiEffect() == false
```

## AC-3: Both Linux targets build and produce loadable artifacts

```gherkin
Given a successful configure
When `cmake --build build-linux` runs
Then the build completes with zero errors
And a VST3 bundle exists containing Contents/x86_64-linux/ForroBox.so and Contents/moduleinfo.json
And the Standalone executable exists and is dynamically linked without missing libraries
```

## AC-4: Processor is silent and safe on the audio thread

```gherkin
Given the plugin is instantiated
When processBlock is called with any buffer size
Then the output buffer is cleared and no audio is produced
And processBlock performs no heap allocation, no locking and no file or logging I/O
And prepareToPlay records sample rate and block size without allocating per-call state
```

## AC-5: Editor holds the design geometry

```gherkin
Given the plugin editor is opened
When its initial bounds are read
Then they are 1200×780
And the editor is resizable with a fixed aspect ratio of 1200/780
And resizing to any width keeps the height at width × 780/1200 within one pixel
And a minimum size of 840×546 is enforced
```

## AC-6: Standalone launches without crashing

```gherkin
Given the built Standalone binary
When it is launched headlessly and terminated after a short interval
Then it starts and exits without a crash, assertion failure or unresolved symbol error
And if no audio device is available on WSL2 it degrades gracefully rather than aborting
```

<task type="auto">
  <name>Task 1: CMake project with JUCE 8.0.12 acquisition and plugin target</name>
  <files>CMakeLists.txt, .gitignore</files>
  <action>
    Create the top-level CMakeLists.txt:
    - `cmake_minimum_required(VERSION 3.22)`, `project(ForroBox VERSION 0.1.0 LANGUAGES C CXX)`,
      C++20, and set CMAKE_BUILD_TYPE to Release when the generator is single-config and no type
      was given.
    - JUCE acquisition, in this order:
      1. Expose a `JUCE_PATH` cache variable (empty by default).
      2. If `JUCE_PATH` is set and `${JUCE_PATH}/CMakeLists.txt` exists, `add_subdirectory` it with
         a binary dir under the build tree, and `message(STATUS "JUCE: using local ${JUCE_PATH}")`.
      3. Otherwise use `FetchContent_Declare(JUCE GIT_REPOSITORY https://github.com/juce-framework/JUCE.git
         GIT_TAG 8.0.12 GIT_SHALLOW TRUE)` + `FetchContent_MakeAvailable(JUCE)` and
         `message(STATUS "JUCE: fetching 8.0.12")`.
      Pin the tag literally — do not track a branch, because an unpinned JUCE turns any future
      build failure into an unbounded bisect.
    - `juce_add_plugin(ForroBox ...)` with: COMPANY_NAME "Forró Box", PLUGIN_MANUFACTURER_CODE
      "Frbx", PLUGIN_CODE "Frbx", FORMATS VST3 Standalone, PRODUCT_NAME "ForroBox",
      PLUGIN_NAME "Forró Box", IS_SYNTH TRUE, NEEDS_MIDI_INPUT TRUE, NEEDS_MIDI_OUTPUT TRUE,
      IS_MIDI_EFFECT FALSE, EDITOR_WANTS_KEYBOARD_FOCUS TRUE, COPY_PLUGIN_AFTER_BUILD FALSE.
      Keep PRODUCT_NAME ASCII ("ForroBox") so artifact paths stay free of non-ASCII, while
      PLUGIN_NAME carries the accented display name the host shows.
    - `juce_generate_juce_header(ForroBox)`, target sources for the four src files, and
      `target_compile_definitions` with JUCE_WEB_BROWSER=0, JUCE_USE_CURL=0,
      JUCE_VST3_CAN_REPLACE_VST2=0, JUCE_DISPLAY_SPLASH_SCREEN=0.
      JUCE_WEB_BROWSER=0 is deliberate — the WebView GUI path is out of scope per PROJECT.md, and
      leaving it on drags in webkit2gtk for nothing.
    - Link `juce::juce_audio_utils`, `juce::juce_dsp` PRIVATE and
      `juce::juce_recommended_config_flags`, `juce::juce_recommended_lto_flags`,
      `juce::juce_recommended_warning_flags` PUBLIC.
    Create .gitignore covering: build*/, _deps/, cmake-build*/, .cache/, compile_commands.json,
    and the JUCE fetch cache.
    Avoid: hardcoding $ENV{HOME}/JUCE anywhere in the file — the local path must arrive only through
    -DJUCE_PATH so the same CMakeLists works untouched on a machine without ~/JUCE (and, in 01-03,
    from the Windows side where that path does not exist).
  </action>
  <verify>`cmake -B build-linux -G Ninja -DJUCE_PATH=$HOME/JUCE -DCMAKE_BUILD_TYPE=Release` exits 0 and logs "JUCE: using local /home/bidu/JUCE"; `cmake -B /tmp/fb-nolocal -G Ninja` (no JUCE_PATH) logs "JUCE: fetching 8.0.12"</verify>
  <done>AC-1 satisfied: configures with the local JUCE and no download. AC-2 partly satisfied: target flags declared.</done>
</task>

<task type="auto">
  <name>Task 2: Silent processor with correct capability reporting</name>
  <files>src/PluginProcessor.h, src/PluginProcessor.cpp</files>
  <action>
    Implement `ForroBoxAudioProcessor : public juce::AudioProcessor`:
    - Constructor: BusesProperties with no input bus and one stereo output
      (`withOutput("Output", juce::AudioChannelSet::stereo(), true)`) — this is an instrument, so
      declaring an input bus would make some hosts present it as an effect.
    - `acceptsMidi() → true`, `producesMidi() → true`, `isMidiEffect() → false`,
      `getTailLengthSeconds() → 0.0`.
    - Program methods: 1 program, index 0, name "Default"; `changeProgramName` a no-op.
    - `isBusesLayoutSupported`: accept only a stereo main output.
    - `prepareToPlay(sampleRate, samplesPerBlock)`: store both in members. Do all sizing here —
      this is the only place allocation is permitted.
    - `processBlock`: `juce::ScopedNoDenormals`, clear every output channel, clear the incoming
      MIDI buffer, return. Nothing else.
    - `getStateInformation` / `setStateInformation`: leave as documented no-ops with a
      `// 01-02: APVTS state` marker so the next plan has an obvious seam.
    - `hasEditor() → true`, `createEditor()` returning the editor from Task 3.
    - `createPluginFilter()` at the bottom of the .cpp.
    Avoid in processBlock, now and forever: `new`/`delete`, `std::vector` resize, `juce::String`
    construction, locks, `DBG`/logging, or anything touching the filesystem. The threading contract
    in PLANNING.md makes the audio thread allocation-free and lock-free, and a skeleton that breaks
    that rule teaches the wrong pattern to every later phase.
  </action>
  <verify>`cmake --build build-linux` compiles with zero warnings from the recommended warning flags; `grep -nE '\b(new|delete|malloc|lock|DBG)\b' src/PluginProcessor.cpp` shows no hit inside processBlock</verify>
  <done>AC-2 satisfied: capability reporting correct. AC-4 satisfied: processor silent and audio-thread safe.</done>
</task>

<task type="auto">
  <name>Task 3: Aspect-constrained editor, then build and smoke-verify both targets</name>
  <files>src/PluginEditor.h, src/PluginEditor.cpp</files>
  <action>
    Implement `ForroBoxAudioProcessorEditor : public juce::AudioProcessorEditor`:
    - Constructor: `setResizable(true, true)`, then
      `getConstrainer()->setFixedAspectRatio(1200.0 / 780.0)` and
      `getConstrainer()->setSizeLimits(840, 546, 2400, 1560)`, then `setSize(1200, 780)`.
      Order matters — calling setSize before the constrainer exists lets the first bounds escape
      the aspect lock.
    - `paint`: fill with the dark chassis colour `0xff141414` (the `--bg` token) and draw the
      product name centred in `0xffe8e8e8` as a placeholder, so a host load is visually obvious.
      Do not build any real chrome here; the chassis is Phase 4 and duplicating it now would be
      thrown away.
    - `resized`: leave empty with a `// Phase 4: scale transform on a fixed 1200×780 child` marker.
    Then build and smoke-verify:
    - `cmake --build build-linux --parallel`
    - Confirm the VST3 bundle layout: `Contents/x86_64-linux/ForroBox.so` plus
      `Contents/moduleinfo.json`.
    - `ldd` the VST3 .so and the Standalone binary; confirm no "not found" entries.
    - Launch the Standalone under a short `timeout` and confirm it neither crashes nor emits an
      assertion; on WSL2 an ALSA warning about a missing device is expected and acceptable.
  </action>
  <verify>VST3 bundle contains Contents/x86_64-linux/ForroBox.so and Contents/moduleinfo.json; `ldd` reports no missing libraries; `timeout 10 ./ForroBox` exits without SIGSEGV or a JUCE assertion</verify>
  <done>AC-3, AC-5 and AC-6 satisfied: both artifacts build, editor geometry is correct and constrained, standalone launches cleanly.</done>
