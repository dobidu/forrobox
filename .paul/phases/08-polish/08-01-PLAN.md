<objective>
## Goal

Opening Forró Box gives you a groove. A fresh instance loads CAMPINA GRANDE for real — its pattern
and its BATERIA mute — instead of lighting CAMPINA over an empty grid and playing silence. A
restored project is untouched.

## Purpose

This is PROJECT.md's own Success Metric, and it is the only one still reading **Not started**:
*"Time from plugin open to a usable groove — under 30 s, zero config."* Today that path produces
silence.

It was recorded at Phase 5's close, assigned to Phase 6, and Phase 6 closed without it. **The user
confirmed it in a real host on 2026-09-21**, during 07-03's checkpoint — which is why it opens
Phase 8 rather than the easter egg.

The user's first instinct was to start in CUSTOM. The design source says otherwise and settles it:
`app.js:757`'s `boot()` calls `loadProfile("campina", false)`, so the prototype genuinely LOADS the
profile at startup and the `false` only suppresses the confirmation flash. Starting empty-and-CUSTOM
would fail the metric outright — open, press play, hear nothing. **The fix is to make the claim
true, not to retract it.**

## Output

- A fresh instance that plays, with no new machinery — `loadProfile` already exists and is correct
- Test rigs that say explicitly when they want an empty grid, instead of relying on a default the
  product is changing
- Checks for both halves: a fresh instance HAS the groove, and a restore does NOT lose the user's
</objective>

<task type="auto">
  <name>Task 1: A fresh instance loads the default profile</name>
  <files>src/PluginProcessor.h, src/PluginProcessor.cpp</files>
  <action>
    Call the EXISTING `ForroBoxAudioProcessor::loadProfile` for a fresh instance, with
    `ids::defaultProfile` looked up through `forrobox::findProfile`. Build no new path: `loadProfile`
    already does the parameter half before the pattern, and its own comment says why — the mute gate
    is applied at SCHEDULE time, so publishing the pattern first would let a step land unmuted and
    ring out for its whole decay. CAMPINA mutes bateria and its four kit lanes are full, which is
    exactly that case.

    IN THE CONSTRUCTOR, and `setStateInformation` is what makes that safe rather than lucky. The host
    constructs, then restores if it has anything to restore, so a real project overwrites the default
    wholesale — `*state = State::readFrom (tree)` plus `apvts.replaceState`. And its existing
    early-returns are load-bearing for AC-3: absent, unparseable or foreign data "leave every
    parameter at whatever it currently holds rather than half-applying", which now means the default
    groove rather than silence. Do not add a second guard beside one that already says this.

    FOUR THINGS ARE ALREADY RIGHT and must not be re-done. The parameter defaults were chosen from
    CAMPINA and match it exactly: bpm 132, swing 38, cachaça 22, timbre HI-FI (index 0). So the
    scalars need nothing. What is missing is only the GRID and BATERIA's mute — do not "fix" the
    scalars into the layout, and do not give bateria's mute parameter a default of `true`, which
    would leak one profile's data into the parameter surface forever.

    Watch `JUCE_ASSERT_MESSAGE_THREAD` in `loadProfile`. If a host constructs off the message thread
    during a scan, that assert fires in Debug. Confirm it holds where this is called, and if it does
    not, say so rather than deleting the assert.
  </action>
  <verify>
    cmake --build build-linux --target ForroBoxTests -j8 && (unset DISPLAY; ./build-linux/ForroBoxTests)
    Expect MANY existing failures — the blast radius below is the point of Task 2, not a surprise.
    Record the count before fixing anything.
    Then run `/code-review` on the diff.
  </verify>

<boundaries>

## DO NOT CHANGE

- `src/Profiles.cpp` and the groove tables. They are generated from `data.js` and cross-checked on
  every build; this plan READS them through `findProfile` and must not touch a digit.
- `ForroBoxAudioProcessor::loadProfile`'s ORDER — parameters before pattern. Its comment records the
  `/code-review` finding that produced it: the mute gate applies at schedule time, so the other order
  lets a step ring out unmuted.
- `setStateInformation`'s early returns. They are what makes AC-3 true, and they were written for a
  reason stated in place.
- Everything Phase 7 shipped. MIDI out shares no file and no mechanism with this.
- The parameter IDs, and the 46 count.

## SCOPE LIMITS

- No `CACHAÇA` easter egg, no Ciclotron™ treatment, no settings menu. Those are the rest of Phase 8
  and they are decoration; this is a correctness fix against a Success Metric.
- The default profile stays `ids::defaultProfile` — this plan does not add a "default profile"
  setting. That would belong to the settings menu, and inventing it here would be a control
  `PLANNING.md` does not specify.
