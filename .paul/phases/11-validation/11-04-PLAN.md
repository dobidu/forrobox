<objective>
## Goal
`type::typefaceFor`'s process-wide cache moves from a function-local `static` into a
`juce::DeletedAtShutdown` singleton. `shutdownJuce_GUI` then frees it when the last instance goes,
which happens before static destruction. The 6 `Typeface`, 6 `FTFaceWrapper` and 1 `FTLibWrapper`
reported at unload stop leaking, and **the pluginval gate passes on every target**.

## Purpose
- It is the gate's last finding (11-01), so this is the plan that makes Phase 11's headline AC
  true: a real validator passes, repeatably.
- In a host, the plugin library is unloaded and reloaded within one process. Typefaces that
  outlive JUCE's teardown hold FreeType state across that boundary.

## Output
- `src/Typography.cpp`: the cache as a `DeletedAtShutdown` singleton, with its lifetime explained
- `scripts/validate-plugin.sh` PASSES on Linux Debug, Linux Release and Windows Release
</objective>

## Measured at planning (2026-09-30)
- **The mechanism.** The cache is a function-local `static`, constructed on ENTRY to `typefaceFor`.
  `Typeface`'s `JUCE_LEAK_DETECTOR` counter is a static constructed later, when the first
  `Typeface` is created inside `createSystemTypefaceFor`. Statics die in reverse order, so the
  counter is destroyed first and reports every Typeface the cache still holds. FreeType's wrappers
  are owned by those Typefaces.
- **It appears only with GUI tests on** (11-01): headless pluginval never paints, so the cache is
  never populated.
- **Every reader and writer is the message thread** (paint, and the UiTest checks at :1044 and
  :1069). `DeletedAtShutdown::deleteAll` also runs on the message thread, so there is no new race.
- No other `static` holds a `juce::Font` or a `FontOptions` in `src/`.
- JUCE's own `TypefaceCache` is exactly this shape (`juce_Font.cpp:53`), and so is the drag pool
  11-02 met.
