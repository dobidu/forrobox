<objective>
## Goal
`createParameterLayout` declares STEPS with `Settings::shared().defaultStepChoiceIndex()` as its
default index, instead of `0`. The constructor's bracketed `writeParameter (steps, …)` is
deleted. The parameter therefore STARTS at the preference: there is no write, no
`parameterChanged`, and no tiling to order around.

## Purpose
- **ROADMAP Phase 12:** "the step-count seed as a declared parameter DEFAULT, not a bracketed
  write".
- **The user's decision at Phase 12 planning:** the declared default, over keeping the write. The
  VST3 then reports the user's preference as STEPS' default, so a host's "reset to default" means
  "my preferred step count".
- It removes a construction-time write whose correctness depended on its position (before the
  tiling baseline) and on the bracketing helper (Steinberg's validator flags unbracketed edits).

## Output
- One line in the layout, one deletion in the constructor, the comment rewritten
- The 08-02 test extended: the DECLARED default follows the preference
</objective>

## Measured at planning
- `createParameterLayout` is static and called once per instance (the `apvts` member
  initialiser), so reading the store there reads it once per construction, which is where the
  write read it.
- The inventory check reads the DECLARED default and expects 16. The suite runs on an isolated
  settings file at defaults (TestMain), so it still reads 16, which is correct: PLANNING.md's
  default is the preference's default.
- `Settings::get` costs about 12 µs (08-02), once per construction.
