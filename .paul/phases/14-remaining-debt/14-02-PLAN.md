<objective>
## Goal
**One rule, one place.** `Chassis::stackOverlays()` raises the three overlays in rank order: kit
panel, then ABOUT, then the wash (`toFront (false)` on each, in turn). It runs once, at the end of
`attachParameters`, after every overlay has been added.

All three are always-on-top **by construction**, so JUCE keeps every later non-always-on-top child
below them whatever the add order (juce_Component.cpp:1214). The relative order inside the group is
then the order `stackOverlays` gave it, and nothing else touches it.

**Deleted:**
- `KitOverlay::setOpen`'s `toFront (false)`;
- `AboutOverlay::setOpen`'s `toFront (true)`. Focus already comes from `grabFocusIfVisible`;
- `Chassis::attachParameters`' `aboutOverlay->toFront (false)`;
- `Chassis::childrenChanged`, the reactive re-fronting of the wash, and its header doc.

## Purpose
- **ROADMAP Phase 14:** "One owner for the always-on-top overlays' z-order — `KitOverlay`,
  `AboutOverlay`, `DrunkOverlay`" (the last is now `EffectOverlay`).
- **The 08-04 deferral, verbatim:** "their relative order is produced by four scattered writes …
  `childrenChanged` is correct and checked, but it is a reactive hook where an ordinal would be a
  rule."
- **A suspected defect to measure first:** `AboutOverlay` is NOT always-on-top today. JUCE's
  `toFront` on a non-always-on-top child stops BELOW every always-on-top sibling. So an ABOUT opened
  while the kit panel is open may sit UNDER it, which contradicts its own comment ("LAST so it sits
  above the kit overlay").
</objective>
