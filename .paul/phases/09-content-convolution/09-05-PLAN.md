<decisions>
## The "different-length variations" clause is NOT built, and that is recorded rather than quiet

`PLANNING.md:844` reads *"8 storable patterns per channel, so channels can run different-length
variations."* The first half is built here. The second half **cannot be built as specified**:
`STEPS` is a GLOBAL parameter (`app.js:581`'s `setSteps`), the grid is five rows of one length, and
the design source has no per-channel length control anywhere. Polymeter would require inventing one,
which PROJECT.md forbids.

Recorded in the ROADMAP too, so it can be reopened as an explicit decision rather than forgotten.

## ACTIVE lanes stay in `State::lanes`; the other seven slots are PARKED

`PatternSnapshot.h:55` is `using PatternLanes = decltype (State::lanes)` — the lock-free handover
copies that array as one block, and the RAII handle publishes it on destruction. Keeping the ACTIVE
patterns in `State::lanes` means **the audio thread's contract does not change at all**: same 256
bytes, same publish, same `processBlock`.

The other seven slots per channel are parked in separate storage. Switching channel C from slot A to
slot B is a SWAP: C's lanes are copied out of `lanes` into A's parking, then B's parking is copied
into `lanes`.

**A parked copy is therefore stale while its slot is active, by design.** That is the one invariant
this model rests on and it must be asserted, not assumed — a reader who takes the parked copy of the
active slot as authoritative gets the pattern as it was when the slot was last left.

The alternative — storing all eight slots and deriving `lanes` on publish — was rejected because it
makes the audio thread's input a computed value rather than a stored one, on the one path this
project has kept allocation-free and lock-free since 02-04.

## An empty slot is empty

Slot 1 holds what the channel plays today. Slots 2-8 start blank. "Storable" is the spec's word;
copying slot 1 into all eight would make eight identical patterns and no way to tell a fresh slot
from a deliberate duplicate.
</decisions>

<boundaries>

## DO NOT CHANGE
- `PLANNING.md`, `forrobox.css`, `controls.js`, `app.js` — READ-ONLY design source. The prototype
  has no slot storage; this plan does not try to give it one.
- **`processBlock` and the lock-free handover.** `PatternLanes` keeps its type and size; the audio
  thread never learns that slots exist. AC-2 is the tripwire.
- Parameter and group IDs in `src/ParameterIDs.h`. `patternSlot()` already exists — use it.
- The grid's edit path. A pad writes the active lane, which is what it already does.
- The groove banks and `assets/profiles.json` — a profile's grooves and a channel's slots are
  different features. Loading a profile fills the ACTIVE slot; it does not touch the parked ones.

## SCOPE LIMITS
- **No per-channel pattern length.** See the decisions section — it is unbuildable without inventing
  a control, and that is recorded in the ROADMAP rather than narrowed silently.
- No copy/paste between slots, and no "duplicate slot" gesture. The design source specifies neither.
- Nothing about the TOP cycler — that is 09-06, and they are different features.

</boundaries>
