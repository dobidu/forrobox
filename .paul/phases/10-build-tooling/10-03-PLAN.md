<objective>
## Goal
`verify-geometry.py` records every enrolled `constexpr` as a declaration with its full scope
(`forrobox::pad::kGap`) in ONE pass. Both consumers, `cpp_constant` (value lookup) and
`check_enrolment_coverage` (coverage), then resolve keys against that same index. A qualified key
matches a qualified declaration. A bare key resolves only when its name is unique. Coverage is
judged per declaration, not per bare-name count.

## Purpose
The gate exists to stop silent coverage loss. Today it has the hole STATE.md's Deferred Issues
records (08-04, `/simplify` altitude): `excused[bare] += 1` drops the scope of a qualified excuse.
**Measured at planning:** delete the `footer::kGap` expectation, add an excuse `nosuch::kGap`, and
the gate exits **0**. The excuse names a namespace that does not exist, and it covers a real 4 px
footer gap that nothing checks. Counting was a proxy for resolution. This plan replaces the proxy
with the real thing.

## Output
- `scripts/verify-geometry.py`: one declaration index, one resolver, per-declaration coverage, and
  a `self_test()` run on every invocation (same pattern as `verify-charset.py`)
- `NOT_COMPARED`: the two bare excuses that the new rule makes ambiguous get qualified
- `10-03-SUMMARY.md`
</objective>

## AC-1: Every declaration is indexed once, with its scope
```gherkin
Given the 18 enrolled geometry headers
When verify-geometry builds its declaration index
Then each `inline|static constexpr int|float|double k…` is recorded once as (scope chain, name, expression, header)
  And the index is built from text with comments and string/char literals removed, so a commented-out declaration or a brace inside a string cannot shift scope
  And `namespace a::b {`, `struct X final : Base {`, `class`, and unnamed blocks (function bodies, initialisers) are tracked, with unnamed blocks adding no scope name
  And the index holds 332 declarations on today's tree
```

## AC-2: Keys resolve by scope, and ambiguity is a failure
```gherkin
Given a key from the expectations table or from NOT_COMPARED
When it is resolved against the index
Then a qualified key `s1::…::sN::kX` matches the declarations whose scope chain ENDS with s1…sN
  And a bare key `kX` matches only if exactly one declaration has that name
  And zero matches fails, naming the key ("names no declaration")
  And more than one match fails, naming the key and every candidate scope ("ambiguous — qualify it")
```

## AC-3: Coverage is judged per declaration
```gherkin
Given every expectation and every excuse resolved to a declaration
When check_enrolment_coverage runs
Then every declaration must be covered by at least one expectation OR one excuse
  And a declaration that is both compared and excused fails (the excuse is false)
  And the planning mutation fails: remove the `footer::kGap` expectation and add the excuse `nosuch::kGap` → exit 1, and the report names both `nosuch::kGap` (no declaration) and `forrobox::footer::kGap` (uncovered)
  And the old dead-excuse check is subsumed by the zero-match failure, not kept beside it
```

## AC-4: One resolver for both value lookup and coverage
```gherkin
Given cpp_constant(name) looking up an expectation's value
When it runs
Then it resolves through the same index and resolver as coverage, and evaluates the recorded expression
  And `scope_block` is deleted if nothing else calls it
  And a constant in a SECOND `namespace pad {` block of the concatenated header resolves correctly (today's first-match `scope_block` cannot see it)
```

## AC-5: The resolver is self-tested on every run
```gherkin
Given a `self_test()` called from main() whose problems join the failure list (the verify-charset.py pattern)
When the gate runs
Then synthetic header text exercises these must-reject cases: wrong-namespace excuse; bare key on a duplicated name; qualified key to a non-existent scope; declaration both compared and excused; declaration covered by nothing
  And these must-accept cases: bare key on a unique name; nested qualification `a::b::kX`; a reopened namespace; a commented-out declaration ignored
  And a regression mutation is caught: restore the scope-discarding rule in the resolver and the self-test alone fails the gate
```
