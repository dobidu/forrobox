<objective>
## Goal
**Sharing a groove is two menu clicks, or one drag.**

**The gear menu's GROOVES band** gains, below Delete:
- `Export groove…` — always enabled (any playing groove can be exported, 19-01).
- `Import grooves…`.

**Export:**
- An async save chooser (`launchAsync`, never modal — 07-02's rule), starting in the user's
  documents folder with `suggestedExportFileName()`, warning before overwriting, filtered to
  `*.forrogroove`.
- Then the preset screen says `EXPORTADO` for ~2 s, or `ERRO: NÃO EXPORTADO` (the 18-02 timed
  message).

**Import:**
- An async open chooser, several files at once, filtered to `*.forrogroove`.
- **Drag and drop:** `.forrogroove` files dropped ANYWHERE on the plugin are imported. A drop
  mixing groove files with anything else is not accepted (the existing audio-onto-a-strip drop is
  unchanged: one audio file, onto a strip).
- **The report**, short, on the preset screen for ~2 s: `1 GROOVE IMPORTADO` / `3 GROOVES
  IMPORTADOS`, with identical ones counted as "já existia" (`JÁ EXISTIA` when nothing new).
- **Only when files were refused,** a dialog (the async native box the sample drop already uses)
  lists each refused file with its reason in plain words — "too large", "not a groove file", ….
- **After an import that added anything,** the side panel shows MEUS, so the new grooves are in
  view. The playing groove does not change (my call — loading one of several imported grooves
  would be a guess; say if you want the first one loaded).

All UI on the message thread; the choosers are held so a second click while one is open is
ignored (the IR chooser's rule).

## Purpose
- **ROADMAP Phase 19:** export/import reachable by a user. Phase 19 and the v0.3 work close with
  this plan; the milestone close (version 0.3.0, tag, draft release) follows as its own step.
</objective>
