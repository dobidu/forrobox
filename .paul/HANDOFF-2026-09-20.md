## READ THIS FIRST

You have no prior context. This document tells you everything.

**Project:** Forró Box — a JUCE 8 VST3 instrument plugin for Brazilian forró percussion: a
five-channel step sequencer with regional groove profiles, a `CACHAÇA` humanisation engine,
synthesised voices and MIDI drag-out.

**Core value:** Producers get authentic, human-feeling Brazilian forró percussion grooves inside
their DAW without hiring a percussionist or programming every hit by hand.

**The design source of truth is the HTML/CSS/JS prototype in this repo** — `forrobox.css`,
`app.js`, `data.js`, `controls.js` — plus `PLANNING.md`. All of those are **READ-ONLY**. Three
verify scripts cross-check the C++ against them on every build, so editing one to match a C++ typo
defeats the point.

## Mental Context — what to carry forward

**The recurring lesson of this project is that a green suite proves nothing about a check that
cannot fail.** Phase 6 produced five fresh instances:

- A "solo is cleared" check passed against a reload that cleared nothing, because the test never set
  a solo first.
- An audio check asserted "finite and still audible" across a profile reload — equally true of the
  profile being replaced, so it would have passed with the publication mechanism deleted.
- A right-click enforcement test passed against three real holes, because its snapshot covered only
  persisted state while the holes changed overlay visibility and the isolated row.
- A pad-flash check compared two readings of the same stale pads.
- A transparency-layer threshold "fix" of 0.995 fixed nothing, because the value it had to clear is
  0.99465 — caught only because the test pinned it from both sides.

**So: always run the mutants, and always `assert` that the mutation applied.** Two mutations in
Phase 6 silently failed to apply and would have read as "not detected".

**And read the REAL exit code.** Twice this phase I grepped build output for `error` and read a
failing build as clean — once running a stale binary through three "passing" runs. The verify
scripts run as their own targets; invoke them explicitly.

**Subagents are useful and not authoritative.** One `/simplify` efficiency agent left 214 lines of
its own instrumentation in `tests/UiTest.cpp` despite being told to remove it. Another reported
`StepPad::flash` as unguarded when it was not. Verify findings before acting on them.
