<objective>
## Goal
Override `processBlockBypassed`, with the behaviour the user chose at planning:
- **Audio:** every output channel is silent. The plugin has no audio input, so delayed silence is
  silence, and that is what makes it match the reported latency.
- **Groove:** the sequencer is FROZEN. The first processed block after a bypass does a CLEAN
  RESTART: voices, the pending queue, the convolver and the mix bus are reset, so nothing stale
  plays.
- **MIDI:** on the FIRST bypassed block, note-offs are sent for every note the plugin had sent
  (`VoiceEngine::flushAllNotesOff`). Incoming MIDI passes through untouched.

## Purpose
- **11-01's gate is red on this:** 500 × `juce_AudioProcessor.cpp:599` per pluginval Debug run.
  JUCE's default `processBypassed` asserts `getLatencySamples() == 0`, and ours is the 32 ms
  lookahead plus the convolver.
- **Two silent bugs sit behind that assert:**
  - Notes sent just before a bypass have their note-offs queued in blocks that never run, so a
    downstream sampler HANGS.
  - Un-bypassing resumes voices frozen mid-decay, plus whatever the lookahead held: old audio and
    a click.

## Output
- `ForroBoxAudioProcessor::processBlockBypassed` and the restart edge in `processBlock`
- VoiceTest checks: silence, the note balance across a bypass, MIDI pass-through, the clean
  restart, and that a run with no bypass is untouched
- pluginval Debug: zero `juce_AudioProcessor.cpp:599`. The gate stays red only on 11-04's leak
</objective>

## Measured at planning (2026-09-30)
- Output buses only: main stereo plus five per-channel stems, and NO audio input. So the
  "identical latency" JUCE's comment asks for is satisfied by silence
- The latency is `outputDelaySamples() + convolver.latencySamples()` (`updateReportedLatency`),
  never 0
- `VoiceEngine::reset`, `Convolver::reset` and `MixBus::reset` are all `noexcept`. Engine reset
  drops the pending-MIDI queue rather than flushing it, which is why the flush happens on ENTRY,
  while a MidiBuffer exists
- JUCE's VST3 wrapper supplies its own bypass parameter when the processor exposes none, and calls
  `processBlockBypassed`. The 47 APVTS parameters are unaffected
- The assertion fires only with pluginval's GUI tests on (11-01); the gate runs them

## Decisions taken with the user at planning
- **Freeze, clean restart** (over keep-running-silent, or JUCE's resume-as-is)
- **Close notes, pass input through** (over swallowing input, or no note-offs)
