<objective>
## Goal
`setStateInformation`, given a blob with Forró Box's tag but no `<STATE>` child:
- applies the blob's parameters, as today;
- restores an **empty grid**, as today;
- marks the state **dirty**, so the UI shows **CUSTOM** instead of presenting an empty grid as the
  unedited default profile.

This is the user's decision at Phase 11 planning, over treating the blob as corrupt.

## Purpose
- The Deferred Issues entry (08-01): "A tagged blob with NO `<STATE>` child restores an empty grid
  still claiming CAMPINA."
- `writeTo` always writes that node, so no Forró Box project reaches this case. A hand-edited,
  truncated or foreign-tool blob can, and the plugin should not then claim a profile it does not
  hold.
- CUSTOM is the `dirty` flag. Like the prototype's `markCustom()`, which sets `dirty` without
  clearing `activeProfile`, the name stays and the tag tells the truth.

## Output
- One clause in `setStateInformation`, with the decision recorded beside it
- The existing "missing state node" test extended to the full semantics
- The Deferred Issues row resolved
</objective>
