<objective>
## Goal
`loadProfile` keeps its `JUCE_ASSERT_MESSAGE_THREAD` for every caller that can run after the object
is shared, which today is the two UI click handlers. The CONSTRUCTOR's default-profile load calls
a private `applyProfile` with no thread assertion, because it runs before any other thread can
reach the object. A new suite check constructs the processor on a `std::thread`. In the Debug
suite, 11-05's counter turns any assertion that construction raises into a failure.

## Purpose
- **ROADMAP Phase 11 scope:** a host instantiating on a loader thread trips the assert in Debug.
  JUCE's VST3 factory takes no `MessageManagerLock`, so the host chooses the thread.
- **Measured at 11-05 planning:** it is the ONLY assertion an off-thread construction fires
  (`PluginProcessor.cpp:238`). pluginval cannot show it, because it constructs on the message
  thread.
- **The constructor's own comment says it was deferred, not weakened:** "an assert removed to make
  a message go away is the guarantee removed with it". The fix keeps the guarantee where it means
  something.

## Output
- `applyProfile` (private, unchecked) and `loadProfile` (public, asserts, then delegates)
- A StateRoundTripTest check: an off-thread construction loads the default groove, and in Debug
  raises no assertion
</objective>
